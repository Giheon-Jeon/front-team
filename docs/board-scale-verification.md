# 모바일 전환 시 보드 자동 확대 보정

2026-10-20 · PR #124 이후 추가 수정

## 재현과 원인

창 높이 900px에서 너비를 1101px → 1100px로 줄이면 원판 너비가 약 545.5px → 900px로 증가
모바일 장면을 무조건 가로 100%, 최대 900px로 표시하는 규칙이 데스크톱 원판의 비율을 덮어쓴 것이 원인

이전 검수는 원판 자체의 종횡비, 클릭 좌표, 배경의 바닥 기준점에 집중
창이 줄어드는데 원판이 커지는 현상과 확대 중 배경·원판의 상대 배율 변화는 검증하지 못함

## 수정

모바일 기본 원판 너비는 다음 세 값 중 가장 작은 값 사용

- 실제 보드 뷰포트 너비
- 1100px 전환 경계의 원래 원판 너비: 1100 × 951 / 1920
- 현재 화면 높이에서 원래 무대가 허용하는 원판 너비: 높이 × 951 / 1080

모바일 메뉴·상태판·안내 글자는 읽기 크기를 유지
기본 장면은 가운데 배치하며 확대 버튼을 눌렀을 때만 큰 장면을 좌우 이동
스크롤바가 나타날 때 기본 너비가 달라지지 않도록 스크롤바 공간 예약

배경은 전체 보기의 배율을 기준으로 계산하고 확대 시 같은 확대 비율을 적용
확대된 페이지 높이로 배경을 다시 맞추던 계산을 제거
가로 이동 중에도 배경 바닥 기준점은 원판과 함께 이동
일반 반응형 화면에서 배경의 화면 덮임은 유지하며, 배경과 원판의 원본 좌표계가 항상 같은 축척이라는 의미는 아님

## 1% 단위 브라우저 검수

`scripts/qa-board-scale.js`를 로컬 프로덕션 빌드에서 실행
517개 단위 테스트와 프로덕션 빌드 통과

| 조건 | 개수 |
| --- | --- |
| 기준 너비 1920px의 100% → 17%, 1% 간격, 높이 5종 | 420 |
| 1100px 전환 경계와 545px 크기 제한 부근 ±5px, 1px 간격, 높이 5종 | 110 |
| 320·390·768·844·1100px에서 장면 확대 100% → 250%, 1% 간격 | 755 |
| 확대 구간별 중앙·끝 가로 이동 | 70 |
| 실제 확대 버튼과 전체 보기 복귀 | 10 |
| 합계 | 1365 |

검사 범위는 뷰포트 너비와 보드 장면 배율
브라우저 설정 메뉴의 페이지 확대·축소 비율을 바꾸는 검수와 구분

모든 조건에서:

- 창 너비를 줄일 때 원판 너비가 증가하지 않음
- 36개 칸의 클릭 영역, 말·주사위와 원판의 좌표 유지
- 배경 한 장이 빈 여백 없이 전체 화면을 덮고 바닥 기준점 유지
- 확대 시 배경과 원판의 상대 배율 유지
- 전체 보기로 복귀하면 원래 크기와 배율 복원

실측 결과:

- 1101px → 1100px: 원판 545.5px → 544.84375px
- 바닥 기준점 최대 오차 0.01042 CSS px 미만
- 칸 좌표 최대 오차 0.01609 CSS px 미만
- 확대 중 배경·원판 상대 배율 변화 0.00343% 미만
- 런타임 오류와 예상하지 못한 API 요청 없음

기존 `scripts/qa-frontend-live-layout.js`의 실시간 크기 변경·주사위·터치·회전·페이지 배치 101개도 통과

## 증거와 범위

로컬 수치: `output/playwright/board-scale/one-percent.json`
화면: 같은 경로의 `fit-*.png`, `expanded-*.png`
실행은 실제 브라우저와 명시적인 로컬 API fixture 사용
운영 API를 바꾸거나 대회 데이터를 수정하는 검수가 아님

PR #124는 main 커밋 17d6f38dc48d189bf3d3b75c281eb7d2ec02b3f8로 병합됐으며 CI #39381672147에서 이미지 발행과 배포까지 성공
이 문서의 추가 수정은 해당 배포 이후 별도로 검증한 내용

기존 배포는 실제 참가자 계정으로 7개 화면 × 7개 화면 크기, 총 49개 상태를 확인
런타임 오류, 실패한 자산·API 요청, 문서 가로 넘침, 깨진 이미지 없음
다만 이 검수에서 1101px → 1100px 전환 시 원판이 약 65% 커지는 결함을 재현했으며, 위 수정은 그 결함을 해결
실제 API에는 공개 KoTH 문제가 없어 운영에서는 빈 상태 디자인을 검수하고 문제 카드 배치는 로컬 fixture로 확인
운영 데이터 변경 요청 없이 조회와 화면 조작만 수행

## 실제 문제 개수가 있을 때의 추가 보정

PR #125를 main 커밋 4fa1ebc566f504266068d6cd94e9965a2dac0117로 배포한 뒤 실제 참가자 데이터로 1% 검수를 반복
320px에서 열린 문제 30개를 표시하면 확대 버튼 문구가 `확대` → `전체 보기`로 바뀔 때 도구줄이 14px 높아지는 조건을 발견
이때 원판 너비는 같아도 배경 너비가 1291.5px → 1334.16675px로 약 3.3% 변함

확대 버튼의 두 문구에 같은 너비를 예약하고 줄바꿈을 막아 도구줄 높이를 유지
열린 문제 버튼은 읽을 수 있는 글자 크기를 유지하며 필요한 경우 같은 위치에서 줄바꿈
`scripts/qa-board-scale.js`의 fixture에도 열린 문제 30개를 추가하고 확대 중 보드의 위쪽 위치가 달라지지 않는지 검사
열린 문제가 없는 상태는 기존 실시간 배치 검수에서 계속 확인
